# 设计说明

## 要解决的问题

「记忆与成长方法」那套约定有效，但依赖人（或会话里的 AI）自觉执行：每次开工先去读 `MEMORY/`，收尾时手动落盘。
现实是会话一多就漏，新会话仍然从零开始。growth-note 把这套约定变成**运行时行为**：

- 读取发生在提示词组装时，不靠模型记得去读；
- 写入发生在回合结束时，不靠模型记得去写；
- 结构化靠工具与固定格式，而不是靠自由发挥。

## 非目标

- 不做全量历史会话的离线检索/向量库。跨会话的经验通过「条目」传递，而不是把旧对话塞回上下文。
- 不做多人共享的云端记忆。数据只在本机。
- 不替代 `AGENTS.md` 里的项目约定。项目规则仍是项目规则；这里沉淀的是**经验**。

## 分层

```
回合进行时        提示词组装 ── 注入摘要（buildDigest）
                  模型按需调用 ── growth_recall / growth_remember
回合结束时        turn-stopping ── 会话笔记（零成本，必做）
                               └─ 每 N 回合 ── 模型提炼 ── 结构化条目
落盘              memory.jsonl（事实） + MEMORY/*.md（视图） + sessions/*.md（原始笔记）
```

三层各自可失效而不互相拖垮：模型提炼失败仍有笔记；视图损坏可从 jsonl 重建；jsonl 是唯一事实来源。

## 为什么摘要这么小

摘要进入系统提示词，**每一步**都要重新付费。所以：

- 每类只取前几条（方法/教训各 5，知识/复盘各 4，状态 3）；
- 每条正文截断到 140~160 字；
- 总预算 `promptBudgetChars`（默认 1800 字符）硬截断；
- 细节留在磁盘，需要时由 `growth_recall` 取。

判断标准：摘要只回答「这次动手前必须知道什么」，不回答「上次具体怎么做的」。

## 为什么不用向量检索

插件零运行时依赖，装不上 Embedding 模型和向量库。替代方案是关键词打分：

- 拉丁词 + 汉字 bigram 分词；
- 标题命中 ×6、标签 ×4、正文 ×2；
- 新鲜度加成 + 被使用次数加成（`useCount` 在召回时累加）。

对「几十到几千条、以中文短标题为主」的记忆库足够；打分可解释，出问题能人工调试。
未来若要语义检索，应作为可选依赖加入，而不是默认路径。

## 记忆范围：两种所有权

| scope | 路径 | 谁该用 |
| --- | --- | --- |
| `global` | `$DSH_HOME/growth-note/global` | 通用方法、读书笔记、个人画像 |
| `workspace` | `<cwd>/.growth-note` | 只属于这个项目的状态与坑 |

**切换只改指针，不搬数据**：两套目录始终独立存在，切回去内容还在。
理由是迁移会引入冲突合并、权限、体积问题，而用户真正的诉求往往是「这个项目别再受别的项目经验干扰」，
隔离比合并更简单也更符合直觉。

个性化开关同理：`PERSONA.md` 一直维护，但只有开关打开时才注入摘要、才参与提炼。

## 事件与生命周期的选择

- `agent/pre-step`（waterfall）：每步之前确保摘要已就绪。首次进入时构建，之后命中缓存。
- `agent/turn-stopping`（serial）：回合关闭前触发。我们**不 await** 长时间的提炼，只把任务丢到后台，
  避免结束回合被模型调用拖住；失败只记 `warn`。
- `agent/created`：预热一次，让第一个回合就有记忆可用。
- `sessionQuery.readSession` 读当前会话事件，失败时回退 `observeSession`。

注入用 `systemPrompt.section`，order 取 `HARNESS_IDENTITY + 50`：在身份之后、具体任务之前，
既不会抢掉系统身份，也不会被后面的任务说明淹没。

## 提炼契约

- 输入：最近 `sessionNotesPerConsolidation` 条笔记（原始文本，含诉求/结论/工具）。
- 输出：`[{kind,title,body,tags}]`，最多 6 条；模型不遵守时用「取第一个 `[` 到最后一个 `]`」兜底解析。
- 强制要求「只写有证据的内容，不写一次性流水」，降低编造与噪声。
- 结果按 `kind + title` 去重：同名条目合并正文并刷新 `updatedAt`，避免同一经验反复堆叠。

## 失败模式

| 失败 | 表现 | 处理 |
| --- | --- | --- |
| 无 LLM / 无默认模型 | 只能攒笔记 | 跳过提炼，工具与摘要仍可用 |
| 提炼超时 / 非法 JSON | 无新条目 | 静默丢弃，笔记仍在 |
| 事件读取失败 | 本回合无笔记 | 下一回合重试（`lastTurn` 不前进） |
| 磁盘只读（工作区 scope） | 写入失败 | `warn`，不影响会话 |
| 条目超限 | 库里条目变少 | 淘汰最久未用的非画像条目，画像永不淘汰 |

## 后续可做

- `growth_export` / `growth_import`：把记忆在机器之间搬。
- 冲突检测：同一标题在新会话里得出相反结论时提示确认。
- 按 kind 配置预算（例如复盘允许更长）。
- 可选的语义召回后端。
